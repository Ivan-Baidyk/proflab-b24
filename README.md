# Виджет формирования КП для Bitrix24

Встраиваемый виджет для карточки сделки Bitrix24. Менеджер ищет позиции в каталоге (PostgreSQL), указывает количество, редактирует уже сформированное КП сделки и отправляет итог в n8n.

**Весь бэкенд (вся работа с БД) выполняется в n8n.** На этом сервере только: отдача SPA, OAuth-обмен при установке и инжект конфигурации/ID сделки.

## Возможности

- Вкладка «Формирование КП» в карточке сделки (`CRM_DEAL_DETAIL_TAB`).
- Autocomplete-поиск позиций по «Наименованию» (debounce 300 мс, от 3 символов).
- Автозагрузка готового КП сделки (если оно уже сформировано) с возможностью редактирования.
- Формирование и отправка КП в n8n (JSON с `deal_id`, данными сделки/контакта и позициями).
- Работает **только из интерфейса Bitrix24** — прямой доступ по ссылке закрыт (HTTP 403).

## Архитектура

```text
Bitrix24 (вкладка сделки) → POST → NPM → Flask (контейнер) → SPA
                                                │
        ┌───────────────────────────────────────┼─────────────────────────┐
        │ BX24.callMethod (сделка/контакт)      │ fetch (3 вебхука n8n)   │
        ▼                                        ▼                          ▼
     Bitrix24 API                     n8n (server.aimentorcrm.com) + PostgreSQL (proflab)
```

Что на сервере (минимум):

| Компонент | Назначение |
|---|---|
| Flask-приложение (`app.py`) | Отдаёт SPA, OAuth-обмен, инжект `window.AI_CONFIG`, защита от прямого доступа |
| `.env` | Конфиг: client_id/secret, домен, URL трёх вебхуков, токены |
| `static/` | SPA: `index.html`, `app.js`, `app.css` |

Что в n8n (вся БД):

| Workflow | Вебхук | Действие |
|---|---|---|
| Поиск каталога | `WEBHOOK_SEARCH_URL` | `SELECT … FROM proflab."Прайсы" WHERE "Наименование" ILIKE …` |
| Загрузка КП | `WEBHOOK_LOAD_URL` | `SELECT … FROM proflab."Готовые КП" LEFT JOIN proflab."Прайсы" …` |
| Создание КП | `WEBHOOK_CREATE_URL` | приём JSON формы КП |
| Единицы измерения | `WEBHOOK_UNITS_URL` | справочник перевода единиц измерения (для выпадающих списков) |

## Требования

- Docker + docker-compose (или Docker с сетью `global-proxy-network`).
- Nginx Proxy Manager (или другой reverse-proxy) для HTTPS.
- n8n с доступом к PostgreSQL (схема `proflab`).
- Локальное серверное приложение в Bitrix24.

## Установка

### 1. Создать приложение в Bitrix24

«Приложения» → «Разработчикам» → «Локальное приложение» → **«Серверное»**:

- «Путь для первоначальной установки» и «Путь обработчика» — публичный URL виджета (например `https://proflab-b24.aimentorcrm.com/`).
- Права: `CRM (crm)` и `Встраивание приложений (placement)`.

Запомни `client_id` и `client_secret` — они понадобятся установщику.

### 2. Подготовить n8n-воркфлоу

Создать три workflow (Webhook → Postgres → Respond) и записать их вебхук-URL:

- **Поиск каталога**: `SELECT "Наименование","Ед.измерения.","Артикул","Цена (оптовая)","Валюта" FROM proflab."Прайсы" WHERE "Наименование" ILIKE '%' || '{{ $json.q }}' || '%' LIMIT 20`.
- **Загрузка КП**: `SELECT k."Нименование",k."кол_во",p."Ед.измерения.",p."Артикул",p."Цена (оптовая)",p."Валюта" FROM proflab."Готовые КП" k LEFT JOIN proflab."Прайсы" p ON p."Наименование"=k."Нименование" WHERE k."deal_id"={{ $json.deal_id }}`.
- **Создание КП**: принимает JSON формы (см. ниже) и пишет/обновляет строки в `proflab."Готовые КП"`.

### 3. Запустить установщик

```bash
git clone <репозиторий> && cd <репозиторий>
./install.sh
```

Установщик запросит (или возьмёт из переменных окружения):

| Переменная | Описание |
|---|---|
| `B24_REDIRECT_URI` | Публичный URL виджета (redirect_uri) |
| `B24_DOMAIN` | Домен портала Bitrix24 |
| `B24_CLIENT_ID` | Код приложения (client_id) |
| `B24_CLIENT_SECRET` | Ключ приложения (client_secret) |
| `WEBHOOK_SEARCH_URL` | Вебхук «Поиск каталога» |
| `WEBHOOK_LOAD_URL` | Вебхук «Загрузка КП» |
| `WEBHOOK_CREATE_URL` | Вебхук «Создание КП» |
| `WEBHOOK_UNITS_URL` | Вебхук «Единицы измерения» |

Можно задать переменные заранее (неинтерактивно):

```bash
B24_DOMAIN=b24-xxx.bitrix24.ru B24_CLIENT_ID=local.xxxx B24_CLIENT_SECRET=... WEBHOOK_SEARCH_URL=... WEBHOOK_LOAD_URL=... WEBHOOK_CREATE_URL=... WEBHOOK_UNITS_URL=... ./install.sh
```

Установщик запишет `.env`, соберёт Docker-образ и запустит контейнер.

### 4. Авторизация OAuth

Установщик выведет ссылку вида:

```
https://<домен>/oauth/authorize/?client_id=...&response_type=code&redirect_uri=...
```

Открой её в браузере (залогинен в Bitrix24) и нажми «Разрешить». Сервер сам обменяет код на токены (пока код не истёк) и зарегистрирует вкладку через `placement.bind`. После этого открой любую сделку — вкладка «Формирование КП» появится.

## Безопасность

- Прямой доступ по ссылке закрыт: Flask возвращает 403, если запрос не из Bitrix24 (нет `code`, `APP_SID` или `PLACEMENT_OPTIONS`).
- `client_secret` и токены хранятся только в `.env` (chmod 600, в git не попадает).
- Вся работа с БД — через n8n; на этом сервере нет доступа к БД.
